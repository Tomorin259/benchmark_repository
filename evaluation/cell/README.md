# Cell-level evaluation

This module contains the public, fixed-reference-30 cell benchmark bundle.
The 14 datasets and 20 registered methods use one shared neighbor contract:
30 neighbors, 30 PCs, Euclidean distance, `X_pca`, and random state 0. The
stored neighbor assets are the reproducibility boundary for Cell evaluation
and for the later Ensemble evaluation.

The PCA used to build each stored graph belongs to the asset-generation
provenance. Installing a graph transfers `indices`, `distances`, and
`connectivities`. Forebrain evaluation separately installs the shared frozen
PCA30 and UMAP2 frames; native input H5AD files remain unchanged.
Ensemble velocity-graph cosines are computed separately in each method's
native `Ms`/`velocity` space on those fixed candidate edges.

## Canonical bundle

The active files live directly below this directory:

- `config.json` — dataset, method, metric, and reference contracts.
- `reference_neighbors/` — one fixed-neighbor NPZ per dataset plus a compact
  SHA256 manifest. Code uses this repository copy by default; pass
  `--reference-neighbors-root` to use an explicitly supplied copy.
- `reference_embeddings/` — frozen Forebrain BATC UMAP2 and its manifest;
  Forebrain PCA30 is retained in `reference_neighbors/forebrain.npz`.
- `results/cell_metrics.csv` — the five primary metrics used in the main
  comparison: Consistency, ICCoh, CBDir, TransCosine, and BATC.
- `results/cell_metrics_supplementary.csv` — supplementary metrics and all
  evaluability counts, including CBDir-HD (`highdim_cbdir`).
- `results/cell_metrics_audit.csv` — logical source locators, source hashes,
  velocity-layer keys, invalid-value counts, and status. It contains no
  machine-specific filesystem paths.
- `results/cell_metrics_edge_details.csv` and `results/tivelo_parity.csv` —
  edge-level detail and the frozen-versus-official TiVelo parity audit.
- `streams/` — all retained stream figures and their render manifest.
- `figures/` — canonical metric panels generated by `plots.py`.

The primary table contains 280 rows. Forebrain CBDir uses the full shared
30-PC transition-mapped velocity projection; its streamlines display the first
two components of that projection. BATC uses the frozen shared 2D UMAP. The
other 13 datasets retain their reference coordinates and existing scores.
`results/forebrain_cbdir_pca_edge_details.csv` records all 120 transition rows;
`results/forebrain_cbdir_pca_manifest.json` binds the promoted scores to native
input hashes, frame identities, software versions and validation. UnitVelo's
exact-zero edge exclusion remains unchanged. DeepVelo's `cell=no-vu` output
remains the selected input; Gene, kinetics and simulation results are unchanged.

## Figure display precision

Display formatting does not change stored results. Individual method-by-dataset
or method-by-transition scores use four decimal places. Summary annotations
(means, standard deviations, medians, macro-averages, branch averages, and
differences between summary values) use four decimal places; dense heatmaps
use two. Formal manuscript numerical
tables use four decimal places, including summary entries. Positive scores
have no leading plus sign, negative signs are retained, and rankings use
unrounded values. Raw CSV files retain their full numerical precision.

## BATC branch-selection policy

The BATC implementation follows GRAVITY's curve fitting, tangent-cosine, and
per-source-cell branch-maximization procedure. GRAVITY selects the best branch
with `np.nanargmax`. The benchmark adds one explicit robustness adaptation in
`batc.py`: branch scores that are NaN are converted to zero before taking the
maximum. This keeps BATC defined when every configured branch score for a
source cell is NaN. It also means that, in principle, a NaN fallback of zero
can exceed a finite negative branch score. This is a benchmark adaptation and
must not be attributed to the upstream GRAVITY implementation.

An isolated original-policy rerun at repository commit `72d6754` used the same
14×20 input manifest, fixed-reference-30 assets, and metric configuration. For
278 of the 280 method/dataset pairs, upstream `np.nanargmax` completed and the
BATC value was exactly equal to the repository value (zero differing pairs;
maximum absolute difference 0). The upstream policy was undefined for two
pairs because at least one source-cell column contained only NaN branch
scores:

- `bonemarrow/TSvelo`;
- `rpe1_gen/TFvelo`.

Those pairs raise `ValueError: All-NaN slice encountered` under the unmodified
GRAVITY branch selector. The complete public Cell table therefore retains the
documented zero fallback. The same-policy check on the 14 datasets and two
Ensemble variants completed for all 28 scores with maximum absolute difference
0, so this audit does not require changes to Cell or Ensemble result tables,
rankings, or figures. The numerical record is summarized in
[`../../docs/fixed_neighbor_reproduction_20260912.md`](../../docs/fixed_neighbor_reproduction_20260912.md).

## Reproduce the evaluation

The large method result files, reference moments, and indicator environments
remain external artifacts. They are addressed through logical manifests and a
caller-provided artifact root:

```bash
python evaluation/cell/run_cell_metrics.py \
  --artifact-root /path/to/artifacts \
  --reference-moments-root /path/to/reference-moments \
  --output-root evaluation/cell \
  --indicators-python /path/to/indicators-python \
  --tivelo-python /path/to/tivelo-python \
  --prepare-script evaluation/cell/prepare_cell_metrics.py \
  --official-script evaluation/cell/score_tivelo_metrics.py
```

`--inputs` and `--config` default to the files in this module: inputs.tsv and
config.json. The defaults are anchored to the module location rather than
the caller's current directory. `--reference-neighbors-root` is optional and defaults to the local
`evaluation/cell/reference_neighbors/` directory. Temporary pair files and
logs go under `--work-root` (or an ignored `.work` directory under the output
root); they are not part of the public result bundle.

A new full rerun also writes `results/cell_metrics_edge_details_extended.csv`.
Its CBDir rows preserve UnitVelo's native edge values as edge means and source
counts. Its BATC rows report each branch's pre-max source-cell candidate mean
and branch-winner count. These diagnostics do not define a new dataset-level
metric or change the five primary scores. Older per-pair caches without the
extended details are recomputed when using `--resume`. Pair caches also bind
source bytes, evaluator/config hashes and metric spaces; old UMAP-only
Forebrain pairs cannot be resumed as PCA30 results.

The optional `preflight_reference30_inputs.py` and
`build_reference_union_moments.py` helpers also take `--artifact-root` and
write logical locators rather than embedding the caller's local filesystem
paths.

## Validate and plot

Run the canonical bundle validator before publishing or handing the assets to
Ensemble:

```bash
python evaluation/cell/validate_results.py
```

The single public plotting entry point is `plots.py`:

```bash
python evaluation/cell/plots.py
```

Use `--metrics`, `--supplementary-metrics`, and `--output` when rendering to a
different location. It produces the five primary panels, the CBDir-HD panel,
and the individual metric files.

## Gene-output-matched cell comparison

The canonical 14×20 Cell tables above remain the paper configuration. A
separate, supplementary comparison evaluates the **gene-analysis H5AD outputs**
for DeepVelo, UniTVelo, and veloVI on the seven real datasets shared with the
Gene module. This produces 21 additional cell-score rows without replacing any
canonical score. DeepVelo uses its `pred_unspliced=true` gene/kinetics output
here; its canonical Cell row continues to use `pred_unspliced=false`.
UniTVelo is the same stored spliced-velocity result with four added gene-analysis
layers: all shared HDF5 arrays, and consequently all six Cell metrics, match
the canonical files exactly. The DeepVelo model output head changes with
`pred_unspliced`, so its spliced velocities also change. Both historical veloVI workflows register spliced `Ms` and unspliced
`Mu` before training. The Cell workflow calls `vae.train()` with package
defaults (up to 500 epochs, batch size 256), then divides its spliced
posterior-mean velocity by the per-gene factor `20 / max(latent_time)`.
The separately saved Gene workflow explicitly requests up to 1,000 epochs
and a hardware-dependent batch size (64 on GPU, 32 on CPU); after training,
it stores the unscaled spliced posterior mean and additionally calls
`get_velocity(velo_mode="unspliced")`. In velovi 0.3.1, this mode selects
the output of an already trained model; it is not a training switch. The
files come from distinct training runs, so their score changes cannot be
attributed to the extra unspliced extraction or to scaling alone. The
DeepVelo and veloVI comparisons measure sensitivity to distinct outputs,
not the effect of merely appending an unspliced layer. For
veloVI/DentateGyrus_lamanno, the two 1,291-gene outputs share 1,290 genes;
this one-gene axis difference also qualifies their direct score comparison.

`gene_matched/inputs.tsv` contains the 21 scored source locators and seven
`scvelo_deterministic` reference-only locators required for the dataset-level
canonical UMAP. Each scored locator and spliced-velocity key is taken from the
`source_h5ad` and `velocity_s_key` columns of
`../gene/results/gene_cbdir_reference30_all.csv`. Cell alignment, fixed 30-NN
assets, reference moments, preprocessing, metric formulas, and TiVelo parity
checks are the same as in the canonical run. `gene_matched/results/` contains
its own primary, supplementary, source-hash audit, edge-detail, and parity
files. Its values are supplementary evidence for matched-input cross-level
analysis and do not change the published 280-row tables or figures.

```bash
python evaluation/cell/run_cell_metrics.py \
  --artifact-root /path/to/artifacts \
  --inputs evaluation/cell/gene_matched/inputs.tsv \
  --reference-moments-root /path/to/reference-moments \
  --output-root evaluation/cell/gene_matched \
  --indicators-python /path/to/indicators-python \
  --tivelo-python /path/to/tivelo-python \
  --prepare-script evaluation/cell/prepare_cell_metrics.py \
  --official-script evaluation/cell/score_tivelo_metrics.py \
  --method deepvelo --method unitvelo --method veloVI
```

## Historical simulation comparison

The three historical simulated datasets have a separate, nine-method
cell-level evaluation under [`simulation/`](simulation/README.md). Its 27
method-by-scenario scores use the same source H5ADs as the simulation Gene
analysis and a shared fixed-30-neighbor reference. Those supplementary results
do not enter the real-data Cell benchmark or its overall ranking.

## Website velocity-field previews

`streams/preview_manifest.json` binds all 14 dataset × 20 configuration previews
back to the exact result locator and SHA-256 in `inputs.tsv`. The existing
40 paper panels remain byte-for-byte retained. Additional previews live under
`streams/previews/`; they do not replace a score, a paper panel, or a method output.
The website copies images only after verifying the complete mapping and image hashes.

`render_stream_previews.py` uses registered source outputs read-only. Direct
projections retain the stored native velocities and reference coordinates;
Forebrain uses the fixed-reference-30 projection sequence from
`prepare_cell_metrics.py` in the scVelo 0.2.5 indicators environment.
The frozen dataset palettes are in `stream_preview_config.json`.
Rebuild into a separate checkout when reviewing a new display bundle:

```bash
python evaluation/cell/render_stream_previews.py \
  --artifact-root /path/to/artifacts \
  --reference-moments-root /path/to/reference-moments \
  --cache-root site/tmp/stream-frame-cache \
  --manifest-root site/tmp/stream-manifests
```

The command writes one manifest fragment per dataset. Assemble a reviewed,
complete 280-entry `preview_manifest.json` before website export. Dataset and
configuration identities come from `inputs.tsv` and the TSV registries.
No method is trained and no evaluation score is computed by this renderer.
