# Signed-T ensemble

This directory contains the two frozen post-hoc ensemble variants used beside
the 20-method benchmark. It is not a 21st velocity method and it never learns
method-identity weights.

The four fixed inputs are TIvelo, veloVI without_vu, DeepVelo's root
deepvelo_*.h5ad family (no-vu), and UniTVelo. The runner reads their logical
paths from config.json relative to an explicit --artifact-root.

Both variants use the scVelo 0.3.4 tutorial post-processing path:

    scv.tl.velocity_graph(adata, vkey="velocity", xkey="Ms")
    scv.tl.transition_matrix(
        adata,
        scale=10,
        self_transitions=True,
        use_negative_cosines=True,
        weight_diffusion=0,
        n_neighbors=None,
    )

The fixed 30-neighbor graph is installed from
evaluation/cell/reference_neighbors/. A different explicitly supplied copy
can be selected through the relative
--reference-neighbor-root override.

For every dataset, the four signed off-diagonal transition values on each
common edge are aligned before aggregation:

- Mean-4: (x1 + x2 + x3 + x4) / 4;
- CenterWeighted-4: after sorting x1 <= x2 <= x3 <= x4,
  (x1 + 2*x2 + 2*x3 + x4) / 6.

The second rule is an order-statistic rule, not a method-specific weight. The
aggregate retains signed values. Its remaining signed-L1 row mass is placed on
the diagonal, and the final embedding vector is generated by calling scVelo's
velocity_embedding with the explicit aggregate T.

The minimum runnable entry point is:

    python ensemble/benchmark.py \
      --artifact-root /path/to/artifacts \
      --output-root ensemble/results \
      --dataset capofibro

Use repeated --dataset arguments to select a subset; omitting it runs every
configured dataset. It writes compact scores.csv, metadata.json, and
summary.md below --output-root, and stream panels under figures/streams/ when
--save-streams is supplied. The optional --h5ad-root writes H5AD outputs to an
external staging directory; H5AD files are not part of the Git module. The CLI
stores only logical artifact paths and checksums in metadata; server-specific
paths are not written to the public result files.

## Independent ranking contract

When `evaluation/cell/results/cell_metrics.csv` exists after a complete run, `benchmark.py` writes `results/rankings_vs_20.csv` and `results/ranking_summary.md`. For each config dataset and metric (`cbdir` or `batc`), the ensemble score is compared once with the 20 Cell methods for that same dataset. The two ensemble variants never enter each other’s candidate set. Rank is `1 + count(method score > ensemble score)`; exact method ties use competition rank and are reported in `tie_count`. The participant count is 21, and no cross-dataset averaging is used for ranking. The only config-to-Cell naming exception is the evidenced `dentate_lamanno` to `DentateGyrus_lamanno` mapping. The completed all-14 outputs are
[`results/scores.csv`](results/scores.csv), [`results/summary.md`](results/summary.md),
[`results/rankings_vs_20.csv`](results/rankings_vs_20.csv), and
[`results/ranking_summary.md`](results/ranking_summary.md); `metadata.json` records
the portable protocol and relative result-file paths.

The reproducible SupFig9 CBDir and BATC panels are rendered by
[`plot_supfig9.py`](plot_supfig9.py) from the canonical Cell and ensemble score
tables into `figures/assembly/suppfig09`; both SVG panels use the same
21-method display order.
